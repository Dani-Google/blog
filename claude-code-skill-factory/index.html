Claude Code Can Now Build Its Own Skills — I Checked the Leaked Prompt

Short answer: The news I saw this post on X and I checked it myself. It's real — but not in the way the post claims. The news

I saw this post on X and I checked it myself. It's real — but not in the way the post claims.

A Spanish developer, Nico Garcia, shared a prompt that supposedly "leaked" — a prompt that makes Claude Code build its own library of Agent Skills from the work you repeat every week. Paste it, and Claude audits your workflow, turns repeated tasks into skills, tests them, and updates them every time you correct it.

The prompt itself is real. I read all 106 lines of it from the video. The "leaked" part is not.

What it actually is

The prompt is a meta-prompt — a prompt that builds skills. It's called "skill-factory" and it works in 8 steps:

  1. Work Audit — finds the tasks you repeat every week.
  2. Correction Log — lists what you always have to fix by hand.
  3. Skill Map — picks the 3 tasks that save the most hours.
  4. Skill Design — names, steps, rules, and examples for each skill.
  5. Trigger Check — makes each skill's description precise enough to fire correctly.
  6. Test Run — runs every skill on a real case and compares it with the manual result.
  7. Learning Loop — updates the right skill after every correction.
  8. Library Plan — ranks the next skills to build by hours saved.

Each skill becomes a SKILL.md file in your project's .claude/skills/ folder. Claude Code loads them on its own, only when needed.

How to use it

Step 1: You need Claude Code — the terminal tool, not the free Claude chat. The prompt is built for Claude Code 2.0 and a real project folder.

Step 2: Copy the prompt (prompt.xml) and paste it into Claude Code in your project.

Step 3: Answer its questions — what you do every week, which tools you use.

Step 4: Let it build the first 3 skills. Review each SKILL.md it creates.

Step 5: Run the test. It runs each skill on a real case and shows the result next to your manual version. If a skill fails, it fixes the skill, not the output.

Step 6: After that, every time you correct Claude, it finds the skill at fault and proposes the fix as a diff. You approve it before it applies.

The honest catches

First, "leaked" is bait. The prompt is a public file on GitHub (prompts/skill-factory/prompt.xml). Nothing leaked — the word is there to make you click.

Second, "works better every day without you touching anything" is not true. The prompt itself requires your approval for every change ("Apply only after the user's OK"). The learning loop is semi-automatic, not fully automatic. You still review, test, and approve.

Third, "in 2 minutes" is hype. The audit, three skills, and test runs take real time — Claude Code has to read your project, build the files, and run the tests. Two minutes is the paste, not the job.

Fourth, you need Claude Code, which is paid ($20/month Pro). The free Claude chat can't run this — it has no project folder and no .claude/skills/ directory.

What should you build first?

Don't build ten skills. Build one — from the thing you correct most often. The prompt calls this the Correction Log: the instruction you keep repeating, the fix you keep making by hand. That single correction, turned into a skill, saves more time than five clever skills you never trigger.

One skill, one job. That's the prompt's own rule.

My best tip

Start with your most repeated correction, not your most impressive workflow. If you tell your AI the same thing three times a week, that's your first skill. Write it down once, properly, and you never say it again.
